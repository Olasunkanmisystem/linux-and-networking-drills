# Repository Structure Explanation

The repository is structured to separate:
- imported historical work (Week 1 and Week 2)
- current workflow evidence (Week 3)

## Structure

imported-submissions/
- Contains real server-based submissions
- Preserves original Week 1 and Week 2 structure

week-03/
- Contains Git workflow evidence
- Contains review documentation
- Acts as a "handover layer" for reviewers

## Why this structure is used

- Prevents mixing old work with new Git workflow evidence
- Makes it easy to validate original submissions separately
- Keeps review steps predictable and linear
- Supports clear traceability from server → local repo → Git history
